# ArclightOS 桌面 0.8.0 完整镜像

本轮独立工作区为 `.local/arclight-0.8.0/`。新文件名沿用维护者增加日期的习惯，使用 `arclightos-trixie-amd64-20261031-0.8.0.iso`；与旧镜像的手动名称 `arclightos-trixie-amd64-20261031.iso` 分开。

输入沿用上一份已验收发行的 1883 包集合，只将 `arclight-desktop` 和过渡包 `yydaniel-desktop` 更新到已构建并通过验证的 0.8.0。AscalonKernel ABI、回退内核、GRUB、安装器及可选 NVIDIA 输入保持原版本和哈希。未修改包保留其真实来源与原始构建记录，不记为本轮重新编译。

`prepare-derived-image.py` 独立复制/绑定已冻结输入，再次验证签名链、逐包哈希和完整源码凭证，并断言只有上述两个桌面包发生变化。`run-image-factory.sh` 从锁定的官方 ISO 解出干净 rootfs，使用无网卡 KVM 构建来宾内的新空白磁盘装配，不复制宿主根文件系统。

新镜像已重新完成 BIOS / UEFI 主内核 Live、两次正常可见的离线安装完成页和移除 ISO 后硬盘启动，以及两个固件下的回退内核 Live。旧验证不会替代新镜像的验证；本轮是否通过及最终哈希以新发布清单和报告为准。

用户授权清理旧镜像。清理在新镜像验证成功之后执行，核对旧文件实际名称、哈希和引用，保留旧源码、许可证和构建/验收记录。旧镜像的 `.iso.7z` 同属旧镜像载荷；官方基础 ISO 是构建输入，另行保留。当前既有安装系统不重新安装、不重启。

构建代理 qemu-ga 的私有状态使用 0077；其维护子进程现通过安全的参数传递显式设置 0022，装配与 GRUB 入口也独立设置同一掩码。封装前还检查两个内核的引导文件、模块依赖/别名/符号索引及镜像凭据对普通用户可读。首轮掩码不合格的可丢弃构建已拒收并保留日志，没有计入验收。


最终 ISO：`arclightos-trixie-amd64-20261031-0.8.0.iso`，3,327,051,776 字节，SHA256 `5f83a7269c16ef2d0975a257901a23a4c93eb0965bc3f58419ca65516264d855`。六份正式报告通过；两份安装后报告各 26 项检查，1872 包精确匹配。23 项封装权限检查通过。真实 Live 中的 0.8.0 编码器产生实时比例、完成加密分卷与校验，另通过 9 项实际 VT 恢复检查。完整镜像验收不等于实体 GPU/睡眠等硬件验收。

旧镜像载荷已在新 ISO 完整验证后清理，包含维护者手动命名的 `.iso` 和 `.iso.7z`，没有删掉旧的对应源码和验收记录。新发布目录为 `ArclightOS-release/20261031-0.8.0/`；不代为压缩或推送远端。
