# ArclightOS 桌面 0.9.1

本版在 `dev` 分支继续 0.9.0 的独显直连、按页应用和原生 OSD 修复，按用户标注整理设置界面。设置程序仍为 C++17 / GTK 3，配色、图标、控件高度和至少 12px 内边距跟随 Pi 桌面。

网络分为有线网络、Wi-Fi、代理、VPN 与其他四个标签页。Wi-Fi 页打开时周期请求扫描并刷新列表，蓝牙页打开时持有本程序自己的 BlueZ 发现会话并持续刷新；离开页面后停止本程序的扫描任务，手动刷新保留。后台查询使用有界线程池，不使“应用”按钮进入忙碌状态；刷新保留未应用的无线/蓝牙开关，不在认证、菜单或模态对话框中重建操作控件。蓝牙停止发现只释放本程序持有的会话。

声音的默认输入、输出设备改用下拉框，各设备音量和静音保留。显示、电源、触控板、输入法、时钟和待应用列表按截图删除重复或实现细节说明；双系统硬件时钟说明使用用户指定的原文。需要重新登录或重启的信息在操作结果中明确显示。

磁盘页合并为设备及分区列表：设备图标、名称和路径为母项，分区名称、路径和实际已用/总容量进度条为子项，所有操作放在 `...` 菜单。通过 UDisks2 提供挂载、取消挂载、检查、修复、改名、加密卷解锁/锁定、属性和弹出；复杂格式化、分区和健康信息通过已有磁盘工具入口处理。GIO 的 MTP/PTP/手机挂载也显示在列表。未挂载的文件系统不凭空猜测已用容量；空 loop 槽和内部交换设备不挤占页面。

设备图标按 PiXtrix 实际可用图标回退，避免 USB、SD 卡或 SSD 显示缺失图标。弹出前重新读取设备状态，检查系统挂载与活动交换分区，依次取消相关分区挂载、锁定加密卷，确认桌面会话经 GIO 发送卸载通知，全部卸载后再调用 UDisks2 `PowerOff`，光驱使用 `Eject`。同一 USB 读卡器的兄弟设备按 UDisks2 的 `SiblingId` 一起检查和列在确认框中；任一分区繁忙或受系统使用时停止，不强制卸载。繁忙时提示“设备正在使用，请关闭相关文件后重试。”，不显示底层 D-Bus 错误。桌面面板能够正确记录安全移除。

持续扫描回归使用独立 D-Bus、模拟 NetworkManager/BlueZ 和私有 Wayland 屏幕，明确不访问实体无线设备。`scripts/build-settings-harnesses.sh` 将测试链接到产品对象；`test-settings-discovery.py` 验证持续发现、退出清理和草稿保留，`test-settings-drafts.py` 检查实际产品的计数与跳转。`test-renamed-desktop.py --page storage` 可只复查存储页的四种布局。存储实操测试须在标记为 `ARCLIGHT_VALIDATION`、无网卡的独立来宾中使用新建 256 MiB 虚拟 USB 盘；序列号、空盘及容量检查不通过时拒绝格式化。常规 `make check` 不会格式化任何设备。

OSD 外框与进度条均为直角矩形，跟随 Pi 主题，音量文字采用真实设备名称加百分比，例如 `Speaker 50%`，不使用 `·`。浮层不抢焦点、不拦截鼠标，约 1.6 秒自动隐藏。

本轮最终桌面工作区为 `.local/dev-0.9.1-release2/`。最终 DEB SHA256 为 `5b8cdaf3cab08a23833e00c71687786632502b1e73335768fd78b4f9dc553b06`。干净构建通过 88 项原生、119 项压缩器和 17 项恢复策略检查；最终包通过 196 项布局、27 项按页应用、8 项 OSD、持续发现与八个默认应用字段定位检查。38 个原生源文件逐一匹配对应源码包，无编译载荷；9 个安装 ELF 与最终 DEB 一致，APT 检查通过。安装前备份为 `/var/backups/arclight-desktop-0.9.1-20261101-r4/`，旧备份链保留，没有重启会话或主动睡眠。

中间候选发现字段名称、图标缺失和面板安全移除误报后均拒收，源码与日志保留。最终 ISO 使用第三份独立冻结输入，不覆盖旧归档。

原始硬件信息和截图保留在忽略目录。独显直连的驱动实测范围见 [实体报告](hardware-validation/2026-10-31-tx-air-fa401km-nvidia-direct/validation.md)；不会把虚拟磁盘或无线协议夹具的结果写成实体 USB、蓝牙或 Wi-Fi 全面通过。新 ISO 的启动及安装验收见 [镜像说明](image-0.9.1.md)。

本机随后实际通过三次 Wi-Fi 扫描请求，以及蓝牙发现启动/退出恢复；连接、蓝牙电源和可发现性设置保持原值。这项服务接口观察见 `scripts/test-radio-discovery.py`，保存在本版冻结输入与最终发布源码中。设备配对、音频传输及实体热插拔仍需分别实测。
