## 启动与性能数据

LightDM 原有单元强制等待 `dev-dri-renderD128.device`。Hyper-V 没有这个渲染节点，导致每次约 90 秒超时。桌面包提供通用 PC 服务单元，去掉固定 DRM 节点依赖；已重新启动验证，无失败的系统服务。

| `systemd-analyze` | 原 Debian 内核 / 修复前 | 新内核 / 修复后 |
|---|---:|---:|
| 内核阶段 | 4.762 秒 | 3.960 秒 |
| 用户态阶段 | 91.435 秒 | 5.666 秒 |
| 总计 | 96.198 秒 | 9.626 秒 |

这些数字不包括宿主固件、Hyper-V 初始化和用户登录。大部分改善来自消除设备等待，不能视为 BORE 的性能收益。

当前内核启动日志确认 `BORE CPU Scheduler modification 7.0.0`，运行时 `kernel.sched_bore = 1`。ISO 的纯软件模拟启动耗时不能用于评估实体机性能。

`perf bench sched pipe -l 100000` 三次结果，单位 µs/op，越小越好：

- Debian 6.12：154.219、152.744、150.559。
- yydanielkernel 7.3：134.447、149.061、153.722。

`sched messaging -g 2 -l 200` 分别为 0.155 秒和 0.260 秒。这是虚拟机单次烟雾测试，存在宿主调度和测量条件差异；不能据此宣称新内核普遍更快。新系统停留在登录界面时内存使用约 699 MiB，不能与已登录桌面或实体机直接比较。
