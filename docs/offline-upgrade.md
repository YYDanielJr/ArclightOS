# 从 ISO 离线升级已安装的 Astgenne OS

本轮提供单独的 **升级 ISO**，不是可引导的安装镜像。不运行 Calamares，不格式化，也不重装系统。2026-10-29 原安装 ISO 继续保留，不具备新的升级清单。

升级介质包含新桌面 DEB、经认证 APT 下载的依赖、逐包哈希、工程源码及构建/下载证据。不需要自建 APT 仓库。安装只使用介质内 DEB，在独立网络命名空间内执行 APT；没有联网补包、删除包、自动清理或自动降级。依赖不满足时停止。现有配置使用 dpkg 的保留策略，账户、分区和个人文件不作迁移。

## 首次从 0.3.2 升级

旧版还没有图形 ISO 升级入口，首次需要运行升级介质附带的引导脚本。先从可信发布说明取得 **整个 ISO 的 SHA256**；不能把镜像自己附带的校验值当作独立的信任来源。

1. 在已安装的系统中校验下载的升级 ISO：`sha256sum /绝对路径/升级.iso`，与可信发布说明逐字比较。
2. 只读挂载这份已经校验的 ISO，例如 `sudo mount -o loop,ro,nosuid,nodev,noexec /绝对路径/升级.iso /mnt`。`/mnt` 应为空且没有现有挂载。
3. 执行 `sudo bash /mnt/upgrade/bootstrap.sh /绝对路径/升级.iso 可信的64位小写SHA256`。
4. 脚本创建仅 root 可读的镜像副本，重新核对完整哈希，再提取原生升级助手；它显示真实依赖计划。确认后输入 `UPGRADE` 才安装。
5. 完成后卸载挂载点，关闭应用并重新登录。内核未改变，无需为了本次桌面升级重编内核或安装 NVIDIA。

不要在升级进行中断电或强制关闭进程。该过程不是整机快照事务；配置和升级前 dpkg 状态会记录，但没有自动撤销全部软件包的能力。建议先备份重要数据。

## 之后的图形升级

设置 → 软件包设置 → 从 ISO 离线升级。选择 ISO，填入可信渠道提供的 SHA256，点击检查；查看拟升级包后再点击安装。安装时重新验证镜像、包载荷和 dpkg 状态；介质或系统状态变化后必须重新检查。

升级助手仅接受 Astgenne OS / Trixie / amd64。需要至少两倍 ISO 大小加 2 GiB 可用空间，并按清单额外核对安装空间；完成后清理私有临时副本。日志位于 `/var/log/astgenne-upgrade/`，默认仅 root 可读。

## 维护者构建

先按 `AGENTS.md` 验证资源、APT 签名链与实际下载路由。只构建修改的桌面包，将新增依赖通过 APT 的 `--download-only` 取得，并保存签名索引、密钥、下载日志与包哈希。不要从不明目录搜集 DEB。

运行 `scripts/build-upgrade-iso.py --pool /受控的DEB目录 --evidence /脱敏证据目录 --source /对应工程源码.tar.xz --release 2026.10.30-desktop-0.4.0 --output /新名字.iso`。构建器拒绝覆写已有 ISO、重复包和错误架构。来源认证是前一步的职责；构建器本身只负责完整性与装配，不能代替 APT 签名验证。

这个升级格式也可以附加到未来完整安装 ISO 的 `upgrade/` 目录中。完整安装 ISO 仍须走独立的启动/安装验收；升级 ISO 的测试不代表新的安装镜像通过验收。
