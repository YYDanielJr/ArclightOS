# AscalonKernel 对 Linux 上游的修改说明

审核日期：**2026-11-01**。适用对象：Linux **7.3** → AscalonKernel **`7.3.0-ascalonkernel`**，Debian 包版本 **`7.3-4+arclight1`**。这是当前已发布版本的来源说明；“建议跟随 stable”不表示源码已经升级到 7.3.1。未来改变源码、补丁或配置须分配新 ABI/包修订并更新本说明。

## 1. 修改范围，先看这张表

| 层次 | 本项目实际做了什么 | 不应混淆的内容 |
|---|---|---|
| Linux 实现源码 | 从锁定的原始 Linux 7.3 出发，应用一份经转换的 BORE 补丁；涉及 14 个文件 | 不是整套 CachyOS 内核，也没有把 NVIDIA 驱动直接并入 Linux 树 |
| 项目对 BORE 补丁的加工 | 删除仅适合 CachyOS 基底的旧代码删除项，修正一个 hunk 的长度；保留补丁新增实现 | BORE 算法属于原作者；7.3 EEVDF 接口适配已经存在于所选 CachyOS 补丁，不是本项目另行原创 |
| Kconfig / `.config` | 以仓库的 Debian 6.12.113 配置为 seed，施加构建脚本覆盖，再运行 7.3 `olddefconfig` | seed 不是 Linux 7.3 的原生 defconfig；全部配置差异不等于全部人工修改 |
| 发行集成 | 独立 release、DEB 版本、image/headers、元包、对应源码、固定构建标识 | 改名、DEB hooks、initramfs、GRUB 配置不等于调度器源码补丁 |
| NVIDIA 支持 | 外部开放模块使用同版本用户态/GSP；7.3 sysfs 兼容补丁应用于 NVIDIA 源码 | 编译/vermagic、真实 GPU 加载、显示/睡眠与 Secure Boot 是不同检查 |
| 桌面恢复 | 当前睡眠恢复保护位于桌面/会话服务与 hook | 不能把它记作已修复了内核的全部挂起问题 |

本次只增加说明、审计快照和源码导出的说明文件；**没有改变当前内核实现、配置、ABI、安装包或启动默认值**。

## 4. 本项目如何转换 CachyOS 的补丁

工程脚本 `scripts/port-bore.py` **只处理 `kernel/sched/fair.c` 中一个指定 hunk**：

1. 所选原补丁以已含 CachyOS 条件分支的源码为基底，hunk 预期删除 `CONFIG_CACHY` 包装及其 400,000 ns 基础时间片、400,000 ns migration cost 分支。
2. 原生 Linux 7.3 没有这些 CachyOS 专有旧行。本项目从补丁的删除项中移除这 9 行，使其匹配原版上下文；保留原版 700,000 ns 基础时间片的非 BORE 分支及 500,000 ns migration cost。
3. 将 hunk 头从 `@@ -81,21 +90,20 @@` 改为 `@@ -81,12 +90,20 @@`。其余 hunks 与所有新增代码保持原输入的内容。
4. 构建执行 `git apply --check` 后才应用；所需上下文不匹配即报错，不静默跳过。

输入 hash 改变、Linux 版本改变或补丁上下文改变时必须重新审核，不能把这个字符串转换器当成跨版本通用移植器。编译树的 `.arclight-bore-applied` 只是复用标记，不能证明任意旧构建树与新锁文件一致；换输入必须使用干净目录。

## 5. 配置：脚本请求与发布结果分别记录

配置 seed 是工程 `config/kernel-base-amd64.config`，文件头为 **Linux/x86 6.12.113**；SHA256 为 `4ea0eceb2fe0b9c301fb4e43dc76b4cd700b6edea6aa30b6fba97c9111006796`。`scripts/build-kernel.sh` 仅在构建树没有 `.config` 时复制它，之后用 `scripts/config` 请求覆盖并运行 `make olddefconfig`。

最终发布快照见 [configs/config-7.3.0-ascalonkernel](../configs/config-7.3.0-ascalonkernel)，SHA256 为 `0be01a983d308d6570f0c2008014e2268c5013c3e8e60913e9340477557b6b43`。

| 配置组 | 构建脚本的明确覆盖 | 已发布配置/边界 |
|---|---|---|
| 调度 | `SCHED_BORE=y`、`PREEMPT=y`、`PREEMPT_DYNAMIC=y`；关闭 NONE/VOLUNTARY；1000 Hz | BORE、动态抢占、`HZ=1000` 均在最终配置中；不能假定所有负载响应都更好 |
| CPU/优化 | `CC_OPTIMIZE_FOR_PERFORMANCE=y`，请求 `GENERIC_CPU=y` | 7.3 最终配置没有旧 `GENERIC_CPU` 符号，实际为 `X86_NATIVE_CPU=n`；`CC_HAS_MARCH_NATIVE=y` 只表示编译器能力，不表示启用了 native。配方不添加 `-march=native` |
| NVMe/引导 | `BLK_DEV_NVME=y`、`EFI=y`、`EFI_STUB=y` | NVMe 内建，配套 NVMe 依赖也随最终 Kconfig 解析；覆盖常见引导需求，不替代实际引导 |
| Hyper-V | `HYPERV=y`；VMBUS/网卡/存储/工具/balloon/鼠标/键盘/DRM 使用模块；关闭 VTL/MSHV root | 上述直接请求已核对；其它 Hyper-V 子驱动不因此自动全开，须按最终配置与 initramfs 逐项看 |
| DRM | `DRM=y`、`DRM_KMS_HELPER=y`、`DRM_SIMPLEDRM=y` | 保留固件帧缓冲和通用显示基础；不是把专有 NVIDIA 驱动编入内核 |
| 内存 | `ZSWAP=y`、`ZRAM=m` | 这是编译支持；不说明运行时已创建 zram 或给定 zswap 策略已生效 |
| 调试信息 | 保留 `DEBUG_INFO` / 工具链默认 DWARF；关闭 BTF、BTF modules、GDB scripts | 最终 `DEBUG_INFO_BTF=n`；BTF modules 的子符号因此可不出现。不能宣称当前 BTF 依赖功能已完整提供 |
| 结构体随机化 | 请求关闭 `RANDSTRUCT` 并选择 `RANDSTRUCT_NONE=y` | 最终为 NONE；未把它描述成没有安全取舍或已完成其它组合的 NVIDIA 兼容验证 |
| 模块签名 | 保留 `MODULE_SIG=y`；关闭 FORCE/ALL；trusted/revocation keys 请求空字符串 | 最终 FORCE/ALL 关闭，trusted keys 为空；部分 revocation 符号不可见。没有继承 Debian 的官方签名，更不等于 Secure Boot 通过 |
| 版本标识 | `LOCALVERSION=-ascalonkernel`、`LOCALVERSION_AUTO=n` | `7.3.0-ascalonkernel`，与旧 ABI 独立 |

**完整差异与归因边界**：seed 与发布快照共 1,208 个不同符号：新增 748、移除 420、共同符号取值变化 40。它们包括跨版本 Kconfig 改名/默认值/依赖、工具链探测和历史已验证配置结果；不能统称“手工改了 1,208 项”，也不能未经逐项推导把每项归因于 `olddefconfig`。完整列表、脚本每个 `scripts/config` 请求及它是否出现在发布配置中，均在 [配置审计 JSON](../configs/config-7.3.0-ascalonkernel.audit.json)。

该 JSON 中 `null` 表示最终文件没有这个符号，`"n"` 表示明确禁用；二者有意区分。例如旧 `GENERIC_CPU`、`PREEMPT_VOLUNTARY` 等请求在 7.3 中不能单靠脚本参数证明生效。最终配置中的其它变化（如 FRED、ACPI platform profile、Hyper-V PCI 子项）同样在完整列表中保留，不编造未记录的修改动机。

## 7. NVIDIA 相关修改位于外部驱动

`scripts/build-nvidia.py` 使用 NVIDIA 开放模块 commit `1a82fbfda8f321b056eb3568850f9316c5e465c5`、版本 **615.78.08**；用户态/GSP 使用同版本官方二进制。原始来源、SHA256 及下面的补丁都锁在 `config/sources.lock.json`。

针对 Linux 7.3 的 `0004-Open-sysfs-config-from-the-userspace-root-on-7.3.patch` 来源仍是固定的 CachyOS commit，SHA256 为 `a6bbae1da91bead7030ed78a161dedd2dc8d38d495ef87af24673642ef1d7ca9`。它只在外部 NVIDIA 模块源码树应用，与 Linux 的 BORE 14 文件补丁分别记录；具体代码应到驱动对应源码及配方审查。

NVIDIA 库放在项目独立目录并通过 GLVND/Vulkan 注册，保留 Mesa；不会运行 `.run` 安装器覆盖宿主系统。模块构建成功/vermagic 相同只代表编译检查，真实显卡、功耗、多屏、睡眠和 Secure Boot 仍各自保留实测边界。

## 8. 本次核验了什么

以完整镜像 **20261101-0.9.1** 对应的固定发布清单为参照：

- `linux-source-7.3.0-ascalonkernel.tar.xz`，194,814,468 字节，SHA256 `f1b18c46f53c1d4d879cdcede90096955ea0f40521d08878a44e3dd8bf154abc`，本次读取核验通过。
- 归档中的 `.config` 与本机 `/boot/config-7.3.0-ascalonkernel` 字节相同，hash 如第 5 节。
- 从固定官方 URL 取得原始 BORE 补丁，SHA256 与锁文件一致；本机转换结果与这里保存的补丁一致。
- 在从已核验归档读取的 **14 个文件的私有副本**上，`git apply --reverse --check` 返回 0。它验证预期 hunks 与发布源码匹配，没有改动归档或运行系统。

**审核限制**：没有重新下载完整原始 Linux 7.3 树并逐文件比较全树，因此这里不是“全树无其它差异”的独立证明，也没有声称本轮重新编译或重新引导。文档明确记录当前配方可识别的改动、补丁与发布文件的匹配和配置证据。原始审计在工程忽略目录 `.local/kernel-audit-20261101/`，公开记录只保留版本、hash 和源码路径，不包含设备序列号/账户等原始信息。

旧冻结归档没有这份新说明，保持旧 hash 不变；后续新导出的对应源码才会携带它。内核升级时先在干净输入上重审补丁和配置、更新本说明与 `maintenance.json`，再构建新 ABI、验证 NVIDIA/引导并保留回退。撤下 BORE 时应从原始源码建立新树；运行时 `sched_bore=0` 不等于恢复了未打补丁的源码/结构布局。
